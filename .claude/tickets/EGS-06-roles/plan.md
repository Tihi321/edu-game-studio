# EGS-06: the role engine, research and the fact base

Phase 3 of the hub plan `HUB-19` (`../creative-hub/.claude/tickets/HUB-19-edu-game-studio/plan.md`), first of three tickets (EGS-06 roles engine, EGS-07 content roles and prompts, EGS-08 the pipeline).
Branch `EGS-06_roles`, cut from `EGS-04_autoplay-bot` (phase 2, EGS-05, is built in parallel in the main checkout; this ticket lives in the worktree `edu-game-studio-p3`). One commit.

## Goal

The engine pieces every content role needs, ported from Scriptorium (read-only source, `../scriptorium`) and adapted to courses:

- the full role list, the seeded config for it (`roles.md`, `quality.md`, `formats.md`) and the model precedence course -> agent -> role;
- the review contract `{verdict, scores, notes, problems}` with `threshold`, `max_rounds`, `revise_below` and `must_pass`;
- the research stack: the `researcher` role, search providers (Tavily, Brave, Wikipedia, DuckDuckGo ..., and `client-search`, where Claude does the web search over MCP), research notes, the course fact base (`factbase/`, stable fact ids, numbered sources, `[n]` / `[fN]` citations) and the `fact-checker` review;
- MCP tools `edu_ask_researcher` and `edu_factbase_get`.

## What already exists (do not redo)

The skeleton copied VN Studio's core: `ModelRouter.candidates(role, {projectModel, agentModel, avoidFamily, visionOnly})` already orders project -> agent -> role and puts `avoid_family` last; the scheduler passes `projectModel: (book, role) => edu.courseModel(book, role)` (a stub that returns undefined); jobs have `avoid_family`, `depends_on`, `round`, `waiting_on`; `buildMessages` / `loadPrompt` / `loadRules` / `render` are in `src/engine/pipeline/prompts.ts`; `chatJson` in `src/engine/pipeline/llm.ts`; the registry already knows `kind: search` providers and `search_order`.

## Steps

1. **Roles.** `src/shared/schemas.ts`: `ROLES` = director, curriculum-designer, researcher, subject-expert, item-writer, misconception-designer, explainer, language-coach, fact-checker, game-designer, narrative-designer, playtester, accessibility-reviewer, child-safety-reviewer, publisher (art-director, art-critic, composer and voice-director come with phase 6). `seed/config/roles.md` lists every role with a model list (writers and designers `[paid, strata, lmstudio]`; checkers and the researcher `[strata, lmstudio, paid]` like Scriptorium) and a short text per role. `src/renderer/ui/roles.ts` `KNOWN_ROLES`: import or mirror the shared list (one-line renderer change, note it for the phase-2 merge).
2. **Course model precedence.** `courses/<slug>/course.md` (frontmatter `kind: course`, optional `models: {<role> | "*": provider/model}`, later `brief`, `run`, `stage`). `EduService.courseModel(slug, role)` returns `models[role] ?? models['*']`, synchronously from an in-memory cache filled at `warm()` and refreshed on every write through the service (and on a file change if the watcher already covers `courses/`). A helper to read and patch `course.md` (`src/engine/edu/course-meta.ts`). Test: a role with a course model uses it before the agent's model and the role list; `*` applies to every role; a reviewer job with `avoid_family` gets a different family first.
3. **Quality and formats config.** `qualitySchema` (as Scriptorium: `threshold` 7, `max_rounds` 2, `revise_below` 7, `must_pass` [fact-checker, accessibility-reviewer, child-safety-reviewer], `weights`) and `formatsSchema` (`config/formats.md`: course formats `{id, label, units, objectives_per_unit, items_per_objective, articles_per_unit, research_questions_per_unit, item_kinds[]}`; seed `quick` (2 units), `standard` (4), `deep` (6), `language-a1`); `factorySchema` gains `research_limit_per_course` (default 40) and `allow_unverified_facts` (default false). Add `quality` and `formats` to the config kinds the engine loads and reloads (same path as `factory`), with `getQuality()` / `getFormats()` on the engine and in `EduDeps`. Seed both files with explanations in the body (no absolute paths: `seed-files.test.ts`).
4. **Reviews and scoring.** `src/engine/review/scoring.ts` ported from Scriptorium `src/engine/pipeline/scoring.ts`: `ReviewResult {role, verdict, scores, notes, problems}`, `reviewSchema` (zod: `verdict: pass|revise`, `scores: record(1..10)`, `notes`, `problems: [{ref, issue, fix?, severity?: major|minor}]`, defaults where Scriptorium tolerates missing fields), `ROLE_DIMENSIONS` for the edu reviewers (fact-checker accuracy; accessibility-reviewer accessibility, readability; child-safety-reviewer age_fit; playtester flow, difficulty; misconception-designer is not a reviewer), `countsAsRevise(review, quality)` (a non-must-pass `revise` counts only with a score below `revise_below`), `weightedScore`, `decide(reviews, quality, gates?)` (must-pass gate, threshold, plus extra hard gates passed in: lint errors, bot failure). `runReview(ctx, {role, task, vars, dataDir})` = `buildMessages` + `chatJson(reviewSchema)` -> `ReviewResult`. Tests ported from Scriptorium's scoring cases.
5. **Search providers.** Copy `src/engine/research/web.ts` (providers tavily, brave, wikipedia, serpapi, serphouse, duckduckgo; `searchTerms`, `excerptFor`, `capText`, `fetchPageText`) and `clientSearch.ts` (the `searcher` / `web_search` client task with `CLIENT_SEARCH_SCHEMA`, `wait_minutes`). Add the `client-search` and free/keyed search rows to `seed/config/providers.md` with `search_order: [tavily, client-search, wikipedia, brave, serpapi, serphouse, duckduckgo]` (Scriptorium's order) and the doc text for them; keep `registry.ts` changes minimal (it already parses `kind: search`; add `wait_minutes` if missing). `SearchService` (from Scriptorium `research/service.ts`) with the budget check and spend rows. Engine option `searchProviders?: SearchProvider[]` (tests inject a fake provider; nothing in a test may reach the network).
6. **Research notes and the researcher.** `src/engine/research/notes.ts` (adapted: notes of a course in `courses/<slug>/research/<n>-<question-slug>.md`, shared notes in `research/`; `findExact`, `available`, keyword match instead of Scriptorium's embedding index: the edu engine has no memory index). `ResearchService.ask({slug, question, purpose, askedBy})`: job id `<slug>--research--q<sha1(questionKey) 8>--r0` (starts with the slug so `edu_status` counts it; deterministic: the same question is never asked twice for a course), `research_limit_per_course`, "no researcher" warning. The `research` job handler ported from Scriptorium `pipeline/researchHandlers.ts` (`check_notes` on matching notes, search, read the top pages, `write_notes` with `wrapUntrusted` pages, the missing-figures follow-up, `search_queries` retry, `from_knowledge` last resort marked unverified, `copiesPage` guard), registered in `registerEduHandlers`. Prompts `seed/prompts/researcher/{check_notes,write_notes,search_queries,from_knowledge}.md` adapted to courses (facts for learners, own words, one claim per fact, dates and figures kept).
7. **Fact base.** `src/engine/edu/factbase.ts`, files in `courses/<slug>/factbase/`: `sources.md` (numbered sources, numbers never change), `facts.md` (facts with stable ids `f1, f2 ...`: `{id, fact, sources: [n], note, topic?, unverified?}`), `merged.md` (notes already merged). `mergeNotes(slug)` adds the facts of new notes (dedupe on normalised text; unverified facts only when `allow_unverified_facts`), `get(slug)`, `factLines(facts)` (prompt lines `[f3] claim (sources [1][4])`), `sourceLines`, `citedFactIds(text)` (`[f3]`, `[f3, f5]`, `[f3][f5]`), `citedNumbers(text)` (`[3]`), `toPack(slug)` -> `{factbase: [{id, claim: 'fact.<id>.claim', source: '<title>', url}], strings: {'fact.<id>.claim': text}}` (one source per pack fact: the first; the pack schema allows one). Unit tests: numbering stays stable across merges, dedupe, unverified handling, citation parsing.
8. **Fact-checker.** Seed agent `seed/agents/fact-checker-<name>.md` and researcher agents (two researchers like Scriptorium), prompt `seed/prompts/fact-checker/fact_check.md` (input: the fact base lines and the unit's articles and items, rendered as text with their ids; output: the review JSON, `problems[].ref` = an item or article id; rules: every claim must rest on a cited fact; a wrong answer key, a distractor that is also true, an explanation that adds an unsourced claim, a citation to a fact that does not say it -> `revise`). A deterministic pre-check `factCheckRefs(...)` (every item names >= 1 existing fact id, every article cites >= 1 and only existing fact ids) whose problems force `revise` regardless of the model. The unit-level fact-check job itself is wired in EGS-08; here: the function `factCheck(ctx, input) -> ReviewResult` and its test with the mock provider.
9. **`_rules.md`** for Edu Studio (`seed/prompts/_rules.md`): the team writes learning content, JSON only when asked, facts only from the fact base with citations, age-appropriate, language of the course, no living-author imitation, no copyrighted text.
10. **MCP.** `edu_ask_researcher {slug, question, purpose?, wait?: seconds}` (creates the research job; with `wait`, waits for it and returns the note's facts), `edu_factbase_get {slug, merge?: boolean}` (facts with ids and sources, notes count; `merge: true` merges new notes first). A `researchTools(svc, def)` list in `src/engine/mcp/tools-research.ts`, spread into `buildTools`. Document both and the client-search loop (`edu_get_task {role: "searcher"}` -> answer `{results: [{title, url, content}]}`) in `docs/mcp-guide.md` (a "Research and the fact base" section).
11. **Tests** (`tests/research.test.ts`, `tests/scoring.test.ts`, `tests/factbase.test.ts`, `tests/course-model.test.ts`, port the relevant cases of Scriptorium's `research.test.ts`, `clientsearch.test.ts` and `reviews.test.ts`): a research job with a fake search provider writes a note with sourced facts; a repeat question is `exists`; the limit; client-search posts a `searcher` task and the submitted results become facts; `from_knowledge` marks unverified and the fact base drops it by default; `decide` gates; course model precedence. `edu-mcp.test.ts` tool list includes the two new tools.

### Deviations and notes

- `SEED_HISTORY` now holds the skeleton's `config/roles.md` and `config/providers.md` hashes (`9e88b188...`, `5aecc020...`), so an untouched data folder from the skeleton gets the new seed; `tests/seed-refresh.test.ts` expected an empty history and was adapted. No seed migration was added: an edited roles.md or providers.md keeps the user's version and the app shows the "update available" warning.
- A client web-search task is filed under the research job's id (`SearchOptions.job`), not under an own `search-...` id as in Scriptorium, so `edu_wait` / `waitIdle` see the research job as waiting for a client (`clientTasks`) instead of blocking until the timeout. A research job on a client model works the same way.
- `ClientTaskQueue.state(id)` added (Scriptorium's queue has it, the skeleton's copy did not; `ClientSearchProvider` needs it). `edu_get_task` says in `output` that a `web_search` task is a web search (same text as Scriptorium's `get_client_task`).
- `EduService.askResearcher` / `waitJob` hold the logic of `edu_ask_researcher` (the tool is thin). `ask` takes `priority` (1 for a tool call, so it goes before the pipeline's own jobs).
- A research job that finds nothing at all (no pages, no knowledge) ends done without a note, as in Scriptorium.
- Brave, SerpApi, SERPHouse and DuckDuckGo are stubs (Scriptorium's state): they throw "not implemented" and are switched off in the seed.
- The mock's `meta.task` of a research job is always `research`; the four researcher prompts are told apart by their text in the tests (`tests/research-helpers.ts`, which also has `runInJob` to run code inside a real job).
- Not run: a live headless engine with a real search provider or a real Claude client (the plan leaves the live check to EGS-08); ComfyUI and the studios are not involved.
