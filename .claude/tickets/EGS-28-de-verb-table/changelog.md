# EGS-28 changelog

## What changed
- `src/shared/lang/de/verbs.ts` (new): `DE_VERBS` (about 185 verbs: sein, haben, werden, the six modals, wissen, tun, strong and irregular verbs, regular verbs, separable verbs, reflexive verbs; levels A1/A2/B1), `findVerb(inf)` (also "sich freuen"), `conjugate(verb, tense, person): string[]` for the tenses `praesens`, `perfekt`, `praeteritum`, `futur1`, `imperativ` (du, ihr, Sie only; modals have none), `konjunktiv2` (special forms plus `würde + inf`; only the special form for sein, haben, werden, wissen and the modals), `tenseForCefr`, `levelRank`. Regular verbs are generated by rules (`-est/-et` stems, `du -t` after s/ß/z/x, `-eln/-ern`, no `ge-` after be/ver/er/ent/emp/zer/miss/-ieren); irregular ones carry principal parts and `presOverrides`.

- `src/shared/lang/de/rules.ts` (new) and `src/shared/lang/index.ts` (new): `rulesFor(lang)` registry, registered for `de` with `promptRules` and `verbTable`.
- `src/engine/edu/lint-conjugation.ts` (new) and `src/engine/edu/lint.ts` (small change: import, three codes added to `LINT_CODES`, `CONJ_VERB_UNKNOWN` / `CONJ_TENSE_LEVEL` added to `WARNING_CODES`, one loop before the shell lint). Copied engine code is otherwise unchanged.
- Tests: `tests/de-verbs.test.ts` (new: 78 golden forms, coverage, invariants), `tests/edu-lint.test.ts` (5 new tests).
- `ROADMAP.md` row.

## Decisions
- **`presOverrides`** has all six slots (`ich`, `du`, `er`, `wir`, `ihr`, `sie`), not only `du` / `er`, because sein and the modals differ in `ich` (and `er` equals `ich` for modals).
- **`promptRules` placeholder:** the plan says whoever lands first owns the German rules text. This ticket created a short placeholder in `src/shared/lang/de/rules.ts` (a TypeScript constant, not `seed/config/language-rules/de.md`; `rulesFor(...).promptRules` is all EGS-30 needs). EGS-30 should replace the text in that file (or move it to a seed file and read it there).
- **Levels:** Futur I is B1 in `tenseForCefr` (EGS-29 teaches it there); Perfekt A2; Präteritum of sein / haben / modals A2, other verbs B1; Konjunktiv II of mögen A1, of sein / haben / werden / modals A2, others B1.

## How EGS-27 connects the lint
The hook reads a raw pack item structurally, so it compiles without the `conjugation` kind: `lintConjugationItem(pack, item, at, resolver)` in `src/engine/edu/lint-conjugation.ts` does nothing unless `pack.targetLang === 'de'` and `item.kind === 'conjugation'`. It reads `item.verb` (text key, resolved in the edition, then the target catalog), `item.tense`, `item.forms[].person` and `item.forms[].answer` (a key; the first accepted entry is the canonical form), exactly as in the EGS-27 schema. `lint.ts` calls it for every item with `kind === 'conjugation'` in every edition. When EGS-27 lands it only has to keep those field names (they are the contract); no change is needed here. If EGS-27 renames a field, change the property reads in `lintConjugationItem`. `CONJ_IMPERATIVE_PERSON` stays EGS-27's: this lint skips a person that the tense does not have.

## Honest limits
- **The table is model-written and has not been reviewed by a native speaker.** The tests check forms that follow from rules of German grammar (regular patterns, stem changes, sein / haben / werden, modals, separable and reflexive verbs, sein-Perfekt); they are spot checks, not a proof. A wrong entry would produce a wrong `CONJ_FORM_MISMATCH` error or hide a real mistake; `CONJ_VERB_UNKNOWN` tells the author to check by hand.
- Not covered: dative reflexives, Konjunktiv I, Passiv (EGS-33), Plusquamperfekt, alternate forms such as "du backst / bäckst". Imperatives of reflexive and separable verbs are generated by rule only.
- The matcher (EGS-26) is not involved: the lint compares normalised lower-case text with the table.
